# Овнезей

Горизонтальная пиксельная текстовая новелла для Android на русском и английском. Рассказчик, диалоги, персонажи появляются слева или справа, выбор кнопками. Сюжет и мир описаны в документе «Овнезей — библия мира».

## Структура

| Путь | Назначение |
|---|---|
| `engine/` | Чистый Kotlin без Android: формат сценария `.ovn`, парсер, исполнитель сюжета, состояние, сохранения, слоты, локализация. Покрыт тестами |
| `app/` | Android-приложение: меню, игровой экран, слоты, настройки, пиксельное оформление |
| `app/src/main/assets/story/demo.ovn` | Заглушка для проверки движка, заменяется сценами сюжета |
| `app/src/main/assets/fonts/` | Шрифт Press Start 2P (лицензия SIL OFL 1.1, файл `OFL-PressStart2P.txt`) |

Зависимостей, кроме Kotlin, нет. Android-модуль использует только платформенные классы.

## Сборка и тесты

Нужны Android Studio (или JDK 17+ и Android SDK 35).

```
./gradlew :engine:test        # тесты движка
./gradlew :app:assembleDebug  # отладочная сборка
```

Версии: Gradle 8.9, AGP 8.7.3, Kotlin 2.0.21, compileSdk/targetSdk 35, minSdk 27 (Android 8.1).

## Формат сценария `.ovn`

Русский текст пишется в основной строке, английский сразу под ней в строке `|en ...`. Если перевода нет, показывается русский текст. Язык переключается в настройках и меняет и меню, и текст в игре.

```
# комментарий
@scenario ovnezey 3        # идентификатор и версия сюжета; версию повышайте при изменении структуры
@character charlie Чарли   # персонаж: идентификатор (ключ портрета) и имя
|en Charlie

@scene start               # начало сцены; сцена start обязательна
@location street Улица     # текущая локация (название при первом использовании), показывается в слотах
|en Street
> Текст рассказчика
|en Narrator text
charlie@left: Реплика      # @left или @right задают сторону, дальше она запоминается за персонажем
|en Line
@set met                   # флаг
@param trust +1            # числовой параметр: +N, -N или =N (отношения хранятся так же)
@give key                  # предмет в рюкзак; @take key забирает
@if trust>=2 & has:key -> scene_b   # переход по условию; @if !met -> ... если флага нет
@goto scene_b              # безусловный переход
@choice                    # выбор, варианты идут сразу под ним
* Взять письмо -> take
|en Take the letter
* Только с ключом -> opened ? has:key   # условие показа варианта
@end                       # конец сюжета
```

### Предметы и осмотр локации

Предметы объявляются блоком `@item` (вне сцены, до или между сценами). Блок заканчивается любой командой на `@`:

```
@item key
name: Ключ
|en Key
desc: Открывает ящик.
|en Opens the box.
use: consume               # consume: расходуется при успешном применении; keep (по умолчанию): остаётся
```

Осмотр локации это сцена, которая заканчивается блоком `@explore`. Он содержит области на картинке, правила применения предметов и реакции:

```
@scene hub
@explore
* box 0.10 0.50 0.24 0.28 Ящик -> box_look ? !box_open   # id x y w h Название -> сцена [? условие]
|en Box
* door 0.84 0.22 0.12 0.52 Дверь -> door_look
|en Door
@use key box -> box_unlock       # предмет на область (можно добавить ? условие)
@use card door -> door_unlock ? box_open
@fail door -> door_wrong         # реакция на неподходящий предмет для области
@fail * -> wrong_item            # общая реакция на любую область
```

- Координаты `x y w h` в долях картинки (от 0 до 1): левый верхний угол и размеры. Область не должна выходить за картинку.
- Нажатие на область переходит в её сцену. Чтобы вернуться к осмотру, сцена области заканчивается `@goto hub`.
- Если для сочетания «предмет и область» нет ни `@use`, ни подходящего `@fail`, игра показывает стандартное «Это сюда не подходит», а состояние не меняется.
- Область с условием, которое не выполнено, не показывается и не реагирует на нажатие.

Подсказка для разметки: в настройках включите «Области нажатия». Все рамки областей будут нарисованы, а долгое нажатие на картинку выведет координаты `x` и `y` в долях картинки.

Условия: `флаг`, `!флаг`, `параметр>=число` (также `<=`, `==`, `!=`, `>`, `<`), `has:предмет`, `!has:предмет`, части через `&`. Неустановленный параметр равен 0.

Правила: идентификаторы только латиница, цифры и `_`. Каждая сцена заканчивается `@end`, `@goto` или `@choice`. Перенос строки внутри текста `\n`. Перевод `|en` должен идти сразу под своей строкой (пустые строки и комментарии между ними допустимы). Ошибки показываются с номером строки.

Тесты проверяют, что в демо-сценарии есть английский перевод каждой реплики, варианта, области, предмета (название и описание), персонажа и локации, что все используемые предметы объявлены, и что сценарий проходится целиком.

## Картинки

Все картинки кладутся в `app/src/main/assets/`, имена файлов совпадают с идентификаторами из сценария:

| Папка | Что | Требования |
|---|---|---|
| `locations/<id локации>.png` | Иллюстрация локации | 320x180 пикселей (или кратно: 640x360 и т. д.), без текста внутри картинки |
| `portraits/<id персонажа>.png` | Портрет персонажа | Пиксель-арт, фон прозрачный |
| `items/<id предмета>.png` | Иконка предмета | Рекомендуется 16x16, фон прозрачный |

Пока файла нет, показывается заглушка: для локации тёмный фон, для персонажа только имя, для предмета первые буквы названия. Картинка локации выводится целым масштабом без сглаживания, по краям остаются чёрные поля.

## Сохранения

Пять ручных слотов и отдельное автосохранение. Автосохранение пишется после значимых изменений (переход в другую сцену, выбор, флаги, параметры, предметы), при сворачивании и при начале новой игры. Оно никогда не записывает в ручные слоты.

Файлы лежат в `files/saves/` приложения. Формат v2: текст в UTF-8, версия сюжета, позиция, флаги, параметры, инвентарь, локация, время записи и контрольная сумма CRC32. Запись идёт через временный файл с синхронизацией и атомарной заменой, поэтому сбой записи не портит прежнее сохранение. Старый формат v1 читается как миграция.

Прогресс не сбрасывается молча. Повреждённое, несовместимое по версии сюжета или от более новой версии игры сохранение не загружается, игрок видит причину, а файл остаётся нетронутым.

## Решения по проекту

- Логическое разрешение арта 320x180, масштаб целыми кратными с чёрными полями (на экранах высотой 720, 1080, 1440 пикселей получается ×4, ×6, ×8). Размер текста подбирается кратным сетке шрифта.
- Свет и фонарик в Ковчеге не реализуются.
- Без геолокации и в полярных широтах день и ночь определяются фиксированным временем: день с 06:00, ночь с 18:00 (этап 3).
- Меню: Продолжить, Новая игра, Загрузить, Настройки.

## Статус проверки

- Тесты движка запускались вне Gradle и прошли.
- Код `app/` проверен компиляцией Kotlin против `android.jar` (API 30) с подставленным `R`. Запуск на устройстве и Gradle-сборка этого этапа выполняются владельцем проекта.
